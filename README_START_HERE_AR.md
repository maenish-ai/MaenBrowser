# MaenBrowser — الحزمة الأمنية النهائية الموحّدة

**تاريخ التجهيز: 22 أكتوبر 2026**  
**القاعدة المستهدفة:** مشروع [maenish-ai/MaenBrowser](https://github.com/maenish-ai/MaenBrowser)، إصدار المصدر 1.9.6 (main).  
**الدمج:** جميع تعديلات حزمة AdFection السابقة + الاستقلال التام عن حجب الإعلانات + حماية التنزيلات والمواقع المخترقة، بما في ذلك التهديدات غير المباشرة لثغرات PHP الصادرة يوم 21 أكتوبر 2026 + ضمان استمرار أوضاع UltraLite/Lite.

## ما الذي تغير؟

### 1) حماية دائمة مستقلة عن مانع الإعلانات

- تعريفات محددة وموثقة من تحقيق Citizen Lab عن AdFection/Candiru: 6 نطاقات تهديدات و8 مسارات تحميل مشبوهة مضبوطة بالمضيف والمسار؛ لا نحظر شبكات إعلانات كاملة أو CDNs سليمة.
- فحص أصلي لجميع طلبات CEF والتحويلات، وفحص الطلبات في نافذة WebView2 الاختيارية عبر محرك الحماية الحالي.
- حجب مسارات التهديدات المعروفة لا يختفي عندما يختار المستخدم `ads=false` أو يضيف استثناءً للإعلانات.
- رفض النوافذ البرمجية المنبثقة دون تفاعل مباشر للمستخدم؛ المحافظة قدر الإمكان على نوافذ الدفع وتسجيل الدخول التي يطلبها المستخدم.
- عرض حالة الدرع الأمني في شارة الواجهة بدل ربط الشارة بمفتاح مانع الإعلانات.

### 2) حماية المستخدم عند زيارة مواقع مخترقة (تحديث PHP)

- بوابة لمنع تنزيل الملفات القادمة من عنوان مصنف ضمن مؤشرات الهجوم المعروفة عندما تسمح CEF باستدعاء CanDownload؛ الاعتراض الأصلي للشبكة هو الحاجز الأساسي.
- تحذير ظاهر وإجبار نافذة `Save As` عند تنزيل الملفات التنفيذية أو السكربتات عالية الخطورة حتى إذا ألغى المستخدم سؤال الحفظ العادي. يمكن إلغاء التنزيل عبر نافذة حفظ Windows/Chromium؛ وليس عبر إسقاط callback بعملية قد تعلّق التنزيل.
- طلب تشغيل فحص سمعة Microsoft SmartScreen في WebView2 عبر `ICoreWebView2Settings8` عند توفره، مع احترام إعدادات الأمان في Windows. **هذا لا يعني توفر SmartScreen لمتصفح CEF نفسه**.
- لا نحجب كل موقع يعتمد PHP؛ المتصفح لا يستطيع ترقيع ثغرات PHP الموجودة على الخادم أو منع سرقة بيانات الخادم. إصلاح الخادم يقع على صاحبه.

### 3) خفّة البرنامج شرط أساسي

- لم نضف خدمات مراقبة أو عمليات فحص خلفية مستقلة أو محرك مضاد فيروسات دائم.
- يعتمد التعرف المحلي على أسماء المضيفين والمسارات وامتدادات الملفات على مقارنات بسيطة، وتحذيرات التنزيل تظهر فقط للامتدادات عالية الخطورة.
- لم نعدّل سياسات اختيار UltraLite/Lite/Balanced/Performance ولا نقايض Sandbox أو Site Isolation أو التحقق من TLS من أجل الأداء.
- يجب قياس الأداء الفعلي على 2/4/8GB RAM قبل إصدار نسخة عامة.

## ما تحتويه هذه الحزمة

- `integrate_maenbrowser.py`: أداة دمج تتحقق من نصوص الكود الأصلي قبل تعديل الملفات، وتصدر ZIP كاملًا من المصدر بعد الدمج عند توفر المستودع محليًا.
- `PREPARE_WINDOWS.cmd`: تشغيل التنزيل والدمج والتصدير تلقائيًا على Windows عند توفر Python وGit والإنترنت.
- `PREPARE_LINUX_MAC.sh`: بديل أنظمة Unix.
- `files/`: الأكواد والاختبارات والمستندات الجديدة؛ تُستكمل الملفات الأصلية بواسطة أداة الدمج.
- `selftest_bundle.py`: اختبارات C++20 المحمولة، وفحص التجميع مع النصوص المستهدفة، وفحوص التصدير والتطبيق مرة واحدة، وفحوص برمجية (ليست إثباتًا لنجاح بناء Windows/CEF).

**مهم:** هذه الحزمة لا تحتوي نسخةً مكتملة قابلة للتشغيل أو جميع ملفات المستودع الأصلية بذاتها. يلزم تشغيل أداة الدمج على نسخة المشروع لتنزيل الكود وإنشاء حزمة الملفات المعدّلة الكاملة.

## تجهيز المشروع كاملاً — Windows

1. فك ضغط الحزمة في مجلد فارغ.
2. ثبّت Git وPython 3.10 أو أحدث (ومع بناء النسخة ثبّت أدوات Windows المحددة في مشروع MaenBrowser).
3. شغّل `PREPARE_WINDOWS.cmd`، أو من طرفية داخل المجلد:

   ```bat
   py -3 integrate_maenbrowser.py --clone --output-dir .\EXPORT
   ```

4. ستجد بعد نجاح تنزيل المشروع ودمجه في `EXPORT`:

   - `MaenBrowser-Patched-Git-Checkout/` — المشروع كاملًا مع `.git`.
   - `MaenBrowser-Changed-Files-Upload.zip` — الملفات المعدلة والجديدة كاملة مع مساراتها، للرفع دفعة واحدة بعد فك الضغط.
   - `MaenBrowser-Full-Source-Merged.zip` — كل ملفات المصدر بعد الدمج (بدون مجلد `.git`).
   - `GitHub-Upload-Changed-Files/` — الملفات الـ23 المعدّلة والجديدة بمسارات GitHub.
   - `maenbrowser-security-integration.patch` — الفروقات للمراجعة.
   - `SHA256-MANIFEST.json` — تجزئات للتحقق من الملفات المصدَّرة.

## تجهيز المشروع إذا كان موجودًا محليًا

```bat
py -3 integrate_maenbrowser.py --repo "C:\path\to\MaenBrowser" --check
py -3 integrate_maenbrowser.py --repo "C:\path\to\MaenBrowser" --output-dir "C:\path\to\EXPORT"
```

تتوقف الأداة قبل أي تعديل عند اختلاف نصوص الملفات عن النسخة التي راجعناها؛ لا تحاول إجبار الدمج على كود مختلف دون مراجعة.

## رفع التعديلات إلى GitHub في Commit واحد

من داخل `EXPORT/MaenBrowser-Patched-Git-Checkout`:

```bash
git status
git add -A
git commit -m "security: consolidate always-on protection and risky download safeguards"
git push origin main
```

إذا كان `main` محميًا، استخدم فرعًا جديدًا وافتح Pull Request بعد اجتياز الاختبارات. **لا ترفع ZIP وحده إلى GitHub** وتنتظر أن تُستبدل الملفات تلقائيًا.

## اختبارات مطلوبة قبل النشر

- شغّل `python selftest_bundle.py` للحزمة، ثم `python tools/run-checks.py` من جذر المشروع المعدل.
- ابنِ Windows Setup وشغّل `ctest` وSmoke Tests عبر CI الحالية في المستودع.
- اختبر أن `ads=false` لا يلغي الحماية الأساسية، وأعد فحص تسجيلات الدخول والملفات التي تنزّل من GitHub والمواقع التي تستخدم Blob وإعادة التوجيه.
- اختبر التحذير والتنزيل ونافذة Save As في نسخة CEF الفعلية، وتأكد من SmartScreen في WebView2.
- قارن RAM/CPU وزمن فتح المواقع على أجهزة 2 و4 و8GB. لا تدّعِ الوصول إلى أداء أو حماية بنسبة 100% دون قياسات.

## حدود صريحة

لم نتمكن هنا من الوصول عبر Git إلى المستودع كاملًا أو البناء على Windows، وتعذرت الكتابة مباشرة إلى GitHub (403). لذلك جرى اختبار أداة الدمج مع ملفات اختبار ذات مواضع مطابقة، إضافة إلى اختبارات C++20، **ولم تثبت بعد عملية بناء Windows أو عدم حصول تراجعات فعلية**. نظام السمعة الشامل أو فحص المحتوى المضاد للفيروسات داخل CEF يحتاج مزودًا معتمدًا وبناءً واختبارًا مستقلًا؛ لا يوجد في هذه الدفعة ادعاء بأنه جاهز.
