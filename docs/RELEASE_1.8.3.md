# MaenBrowser 1.8.3 — الأداء والتنزيلات

## ما تغير فعلياً

1. **سطح WebView2 المخفي:** مزامنة `IsVisible` مع ظهور التبويب وتصغير نافذة المتصفح. النسخة السابقة أخفت النافذة الأم دون إبلاغ المحرك. أُضيف تجميع لأحداث تغيير الحجم ومنع إرسال الأبعاد ذاتها مراراً. لا تعليق قسري لواتساب أو المكالمات أو التنزيلات، ولا إجبار للذاكرة على الانتقال إلى القرص.
2. **اكتمال التنزيل:** إزالة حوار `MessageBoxW` الإضافي الذي يعترض خيط واجهة المتصفح. يبقى عرض التنزيلات الأصلي وأزرار فتح الملف/المجلد عند طلب المستخدم. لم نغيّر اختيار مجلد الحفظ أو فحص أمان التنزيل.
3. **شاشة التنزيلات:** سرعة مقاسة من فرق البايتات والزمن، المنزّل/الإجمالي، شريط تقدم ووقت متبقٍ تقريبي. تحديث مرة كل نحو ثانية أثناء عرض الشاشة ووجود تنزيل جارٍ؛ لا تحديث دوري عندما تكون مخفية أو عند انتهاء التنزيل. يعاد استخدام عناصر الصفوف بدل بناء القائمة كاملة مع كل تحديث. الحجم المجهول والسرعة قبل توفر عينتين لا يُعرضان كأرقام مختلقة. التنزيلات الخاصة بمحرك واتساب تظل في واجهة تنزيلات WebView2 الأصلية.
4. **فحص الطلبات:** لا استعلام عن الإطار الرئيسي لكل مورد عندما لا توجد استثناءات إعلانات. قوائم الحماية المرتبة مسبقاً لا يعاد فرزها؛ القوائم المخصصة تبقى مُتحققاً منها ومرتبة.
5. **الوضع الخفيف:** استخدام تصنيف المعالج المحدود الموجود أصلاً (أربع وحدات منطقية أو أقل)، بدلاً من الاعتماد على RAM وحدها. لا إلغاء للعزل أو حماية TLS أو تسريع الفيديو/GPU. سياسات ذاكرة التخزين المؤقت السابقة لم تُعدَّل.
6. أداة قياس اختيارية في `tools/measure-windows.ps1` تشمل المتصفح وعملياته التابعة: CPU والذاكرة وقراءة/كتابة العمليات، مع مواصفات النظام. لا تعمل تلقائياً، ولا تجمع عناوين المواقع.

## تفسير حدود النتيجة

لمبة الجهاز لا تقيس نسبة CPU أو RAM أو تحدد أن السبب المتصفح. الصور تُظهر واتساب وصفحة GitHub؛ تشغيل WhatsApp عبر WebView2 مع صفحات CEF يعني وجود محركين وقد يزيد الاستهلاك. الإصدار الحالي يخفف العمل غير الضروري؛ لا يلغي تكلفة المحركين. نقل المشروع إلى لغة أخرى لن يُثبت تحسناً تلقائياً، فهو يستخدم C++ ومحركات Chromium بالفعل.

هذه إصلاحات لمسارات لوحظت في الكود، وليست تشخيصاً مؤكداً لكل البطء على الجهاز. تأخر أول بايت قد يأتي من الخادم/الشبكة، وتأخر ظهور الملف قد يرتبط بالقرص أو الفحص الأمني. لم نلغِ فحص الملفات أو الحماية لتسريعها. لا وعد بأنه أخف من Chrome/Edge أو بنسبة تسريع قبل قياس نفس الحمل على نفس الجهاز.

- لم تُقَس موارد الجهاز الظاهر بالصورة، ولم تُختبر نسخة Windows الجديدة في بيئة التطوير هذه.

## التثبيت والتجربة

ارفع محتويات ZIP إلى جذر المستودع مع `.github` واستبدل الملفات. بعد نجاح Actions، نزّل وثبّت **Setup 1.8.3** وأغلق النسخة القديمة. رفع المصدر لا يحدّث البرنامج المثبّت.

لإظهار السرعة: افتح زر الحماية ثم «التنزيلات». سرعة النقل تُقاس وليست زيادة في سرعة اتصال الإنترنت.

اختبر فتح صفحة، وتنزيل ملف، ثم واتساب بالخلفية والتصغير/الاستعادة والمكالمات. للتشخيص الإضافي أرسل صورة «إدارة المهام» بأعمدة CPU وMemory وDisk أثناء البطء، مع RAM ونوع القرص HDD/SSD إن عُرفا.

قياس اختياري (PowerShell من مجلد المشروع، دون تغيير ExecutionPolicy):

```powershell
.\tools\measure-windows.ps1 -Seconds 60 -OutputPath "$env:USERPROFILE\Desktop\maen-performance.csv"
```

إن منعت سياسة الجهاز تشغيل السكربت، استخدم إدارة المهام. ملفات النتيجة CSV وملف hardware.json المرافق لا تحتوي روابط التصفح. قراءة/كتابة العمليات تشمل الشبكة والأجهزة وليست قراءة/كتابة القرص الفيزيائي وحده. القياس يستثني فروق عمليات ظهرت أو اختفت بين عينتين، وجمع Working Set يشمل صفحات مشتركة؛ لا تفسّره باعتباره قياساً مثالياً لكل RAM.
