# Download popup lifecycle change

Base: `f8f3331deabc138c261dc86f9291af1158365fbd`. The original request, cookies, method, referrer, body and redirects are not replayed. On an in-progress download with a chosen path, the Windows client hides only an isolated CEF popup whose main document is still empty, if another browser window exists. Its browser remains alive for the transfer. A successfully completed download can close that empty isolated popup only when no associated downloads remain. A failed or interrupted transfer shows it again, and navigation to a real page unhides it. Shared windows and populated pages are not hidden or closed. This does not guarantee suppression of popups that CEF does not identify as popups, tabs, or pages that commit a document.

The Windows integration smoke now uses slow POST and redirected downloads with original-context checks, checks visible process window count during each transfer and confirms final file bytes. Portable checks do not execute this Windows GUI test. This change has not been run on Windows or tested against the live GitHub website in this workspace; the GitHub Actions Windows run and a manual GitHub download are required to establish the behavior.
